## 可复现开发验证

每次任务开始遵循根目录 `AGENTS.md`：检查工作区变更、运行时版本及锁文件，执行准备脚本并获取测试基线。准备脚本及测试入口以根目录 `README.md`、`package.json` 和 `pyproject.toml` 中最终定义的命令为准。

依赖变更后重新按锁文件安装，确认已有 `.env` 被保留、示例不含真实密钥、准备流程未改写锁文件。完成前执行项目静态检查、相关测试、构建与 `git diff --check`；只记录实际执行结果。

## 本地浏览器验证

使用本地受控页面覆盖加载、通用可见状态、失败、敏感内容脱敏和会话清理。测试页面只属于测试环境，不能因方便测试而允许生产接口任意访问内网地址。

无图形桌面的环境可以使用无头 Chromium 检查浏览器自动化基础功能。这仅证明工具能操作浏览器，不证明用户可以在当前云端手动登录。人工登录的验收必须使用用户可以实际操作的有界面浏览器。

前端交互至少验证：输入活动 URL、展示验证错误、创建会话、看到计时/状态/事件、手动请求观察、停止会话及失败反馈。自动浏览器集成测试只访问本地页面。

## 真实平台观察测试

ALL TICKET 优先，TTM 单独安排。用户已经提供目标和参考活动 URL，见 `ALLTICKET_RESEARCH.md`；实际测试需在用户本地可操作的浏览器中人工登录。参考链接末尾分号的处理、官方开售日程及当前可售状态均需核实。

2026-10-17 的云端 HEAD 检查在代理 CONNECT 阶段返回 HTTP 403，不属于平台页面测试。只有连接到官方页面并取得可观察结果，才能记录对应平台的页面证据。

每次只进行保守的用户发起导航，记录日期、时区、活动范围、加载耗时、可见状态及错误。不自动点击真实座位、提交订单、支付、刷新竞争库存或处理验证码/排队。将结果写入对应平台研究文件；没有真实平台证据时明确标注“未执行”。

## 后续 M3/M4

在本地模拟器验证 100～500 座位、多票档/区域、随机库存变化、并发选择、锁定超时、网络延迟和冲突。固定随机种子或记录实验配置，使实验可重放。

每种策略进行多次实验，记录样本数量、条件、结果分布和失败原因。指标包括 Seat Discovery Time、Selection Time、Reservation Success Rate、Conflict Rate、Error Rate；先统一定义和分母，再比较人工与辅助流程。不得用真实平台压测来替代模拟器。
