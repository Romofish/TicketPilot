## M1：基础工程

- 后端：Python 3.12+、FastAPI。
- 前端：React + TypeScript。
- 浏览器：Playwright；测试：pytest 及浏览器测试基础设施。
- 本地持久化使用 SQLite。M2 通过每 2 秒轮询本地 API 更新研究记录，此轮询不访问或刷新票务平台；原建议的 WebSocket 作为后续传输选项，当前未交付。
- Python 和 JavaScript 的直接依赖、锁文件、运行时版本均可追踪；安装依赖不依赖一次性手工操作。
- 提供可重复执行的准备脚本、无真实密钥的 `.env.example`、启动说明和基本测试。
- 在 `AGENTS.md` 记录每次任务开始时的依赖检查、基线测试、完成前验证，以及依赖变更后的同步维护规则。
- 准备流程保留已有 `.env`，不自动更改云环境基础配置。确需基础配置调整或新增密钥时告知用户。

## M2：浏览器研究

- 用户输入活动 URL，并明确选择或识别为受支持的平台。
- 后端通过 Playwright 打开真实浏览器；人工登录发生在该浏览器中，应用不收集登录表单中的账号密码。
- 保存必要的活动基本信息、观察时间与所属平台。
- 记录页面导航和加载耗时；区分不同计时口径与加载失败，不能把失败显示为成功。
- 展示当前可见页面状态；缺少证据时返回“未知”，不伪造平台专属 CSS Selector、API、座位状态或锁票规则。
- 允许用户在正常浏览过程中观察和记录可见座位状态；M2 不承诺自动解析平台座位布局。
- 记录脱敏调试事件、页面异常和加载失败；保存结果可供后续分析。
- 平台相关逻辑放入各自 Adapter；通用会话、计时和记录逻辑可复用。
- 会话停止时释放浏览器资源；浏览器无法启动时给出可操作的错误信息。

## 真实平台操作边界

- 工具不得自动提交订单、占用座位、支付或重复尝试预订。
- 不绕过验证码、排队、访问限制、购买数量限制及平台风控。
- 真实平台只做保守频率的用户发起观察；不通过真实站点的高频访问测量并发和冲突。
- 对未知页面先观察、记录，再决定是否添加结构识别。研究结论必须注明日期、活动范围与证据。
- 不在代码、Git、数据库、日志或导出结果中保存账号密码、Cookie、Token、支付信息；不要记录原始请求头、请求体、响应体或整页 HTML。
- URL 查询参数、片段及可见内容可能含敏感信息，写入日志前必须执行脱敏；外发分享前继续遵守同一规则。

## 后续里程碑范围

- M3：100～500 座位的本地模拟器，包含票档、区域、库存变化、多用户、锁定及超时、网络延迟和冲突。

- M7：异常恢复、资源清理、日志脱敏与整体稳定性验证。

## 验收与使用前提

M1 需证明 API 与前端可以启动、基础测试通过；M2 需证明活动会话能打开浏览器并保存观察记录，本地测试验证可重复性。真实 ALL TICKET/TTM 验证单独记录，不以本地测试代替。

人工登录要求用户能操作**后端所在机器**的浏览器。用户已选择在自己电脑本地运行；云端仅用于开发和测试。M1/M2 不隐式安装远程桌面、改变网络配置或引入平台密钥。

用户提供的目标活动、参考活动及已被后续澄清取代的开售时间回忆保存在 `ALLTICKET_RESEARCH.md`。URL 用于确定研究对象；实际开售日程、当前活动状态和购票规则必须从官方活动页面核实，并记录来源与适用范围后才能用于规划。
