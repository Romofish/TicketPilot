## 验收记录与 Release 交付标准

每条证据使用以下最小结构，区分公开内容提取、真实平台互动及应用集成；缺失信息写“未知/未执行”，不补造具体时刻或结果：

```text
记录编号 / 观察日期时间与时区：
证据类别：公开内容提取 / 平台互动 / TicketPilot 集成 / Release 资产
活动及安全来源 URL（去除查询参数与片段）：
验收编号与前提：登录状态、执行通道、授权范围
实际动作与观察事实：
状态：已观察 / 阻塞 / 未执行；失败或停止原因：
脱敏证据摘要及适用范围；尚未验证的下一步：
应用版本：平台独立取证时不适用；集成时填写提交 SHA、修改状态、资产 SHA 和应用事件编号
```

每次实际执行需产出可复核的记录，至少包括：

1. 执行时间与时区、活动、安全来源 URL、云环境与浏览器版本。
2. TicketPilot 完整提交 SHA、应用版本、是否存在未提交修改，以及该版本对应的 Release 地址和资产名称。
3. 每个步骤的实际操作、观察结果、通过/失败/未执行状态及原因；平台事实与推测分别记录。
4. 必要的脱敏结构化证据及事件编号，不收集密码、Cookie、Token、完整证件、付款码或原始支付报文；证据不足时明确记为待验证。
5. 未完成与失败项目、复现条件、修复版本及必要复验结果。修复后不得沿用旧版本的通过结论。
6. Release 状态、源码包和 `SHA256SUMS` 等资产的实际存在情况；从 Release 回下载资产，计算 SHA-256 并核对校验文件，再确认包内版本与被验收提交对应。

分支名不是 Release；创建 Release 记录也不等于资产上传、可下载及校验完成。草稿、预发布与正式发布状态应如实说明。云端验收所用版本和最终资产必须可追溯到相同源码；若第三方云浏览器先完成平台取证，应分别标注“平台流程观察结果”与“TicketPilot 集成结果”，不能合并为全部通过。

本文件不填写尚未产生的 Release 资产校验值或未完成的真实操作结果。实际发布及资产核验由 [发布说明](RELEASE_NOTES.md) 和 [项目计划](PROJECT_PLAN.md) 记录；只有对应证据齐备，才能更新验收结论。
