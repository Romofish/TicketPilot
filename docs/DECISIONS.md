# 工程决策记录

记录日期均使用 Asia/Shanghai；本次初始日期：2026-10-17。

## D001：ALL TICKET 优先

用户明确调整原交接文档顺序。M2 优先完成 ALL TICKET 浏览器研究入口，保留独立 TTM Adapter；M5 为 ALL TICKET 选座辅助，M6 再深入 TTM。紧迫的购票需求不改变人工确认和平台规则约束。

## D002：先交付 M1/M2，再用证据扩展

当前实现 FastAPI、React + TypeScript、Playwright 及基础测试，交付可运行的观察工具。M3 模拟器、M4 性能实验和真实平台选座辅助保留为后续里程碑，不以猜测的平台逻辑提前填充。

## D003：平台 Adapter 独立

共用会话管理、计时、存储和事件传输；平台识别和后续页面规则保留在各自 Adapter。没有真实证据时使用明确的未知状态，不硬编码猜测的 Selector、私有接口或锁票规则。

## D004：人工登录默认在本地后端浏览器进行

Playwright 浏览器运行在后端机器。用户已确认在自己电脑同时运行后端和前端；账号登录由用户在浏览器中完成。

当前云开发环境没有可供用户交互的图形桌面。无头浏览器适合自动化测试，不能完成需要用户操作的登录体验。若希望在云端使用有界面浏览器，需要先明确可访问桌面方案；基础环境配置调整另行告知用户，不隐式安装远程桌面或修改网络。

## D005：最小持久化与脱敏

SQLite 保存需要复查的会话和脱敏观察事件。M2 工作台每 2 秒轮询本地 API 读取记录，轮询不触发平台刷新、导航或库存访问；WebSocket 保留为后续传输选项，当前不宣称已实现。研究日志尽量采用结构化、最小字段，不保存原始网络内容、浏览器凭据或支付信息。页面文本与 URL 也按潜在敏感输入处理，不能认为“用户可见”就可原样记录。

## D006：保留可复现环境约定

同时维护 Python 和 JavaScript 的依赖清单、锁文件及运行时声明。准备脚本可重复执行、遇错退出并保留已有 `.env`；新增依赖时同步检查准备脚本、环境变量示例、`AGENTS.md` 和开发说明。常规仓库内依赖安装直接完成；基础云配置或新增密钥需求向用户说明。

## D007：本地工具测试与平台事实分开

本地固定页面验证工具正确性；真实平台研究记录活动范围、日期、人工步骤及证据。只有实际执行的测试才写入里程碑结果，只有观察到的现象才写成平台事实。UI 启发式识别不构成服务端锁票机制证明。

## D008：本阶段不自动触发真实购票动作

M2 只负责用户发起导航、页面观察和记录，不执行自动选座、确认预订、订单或支付。T1/T2/T3 保留为研究问题；T2/T3 如有证据，来自用户自行进行的正常流程。验证码、队列和平台限制始终按官方流程处理。

用户要求创建 GitHub Draft Release。先完成可重复安装、本地测试、交付物与说明，再创建发布草稿及上传产物。当前 `gh api user` 被云网络访问限制阻断，GitHub 认证与发布权限尚未验证；不把 Forbidden 直接归因为凭据失效。

目标活动、参考活动以及“明天泰国时间 11:00”是用户提供的信息。参考 URL 末尾分号暂按标点处理，但原始输入与规范化候选同时保留，尚未验证地址有效性。日期换算注明客户端日期和两个时区，不将其写成已核实的官方开售公告。
