# 产品目标

更新日期：2026-10-17（Asia/Shanghai）。优先平台：ALL TICKET，其次 TTM。

核心目标是研究官方正常购票流程，识别操作瓶颈，逐步提供可靠的选座辅助、状态监测和异常提醒。工具不承诺抢到票，也不以高频刷新作为核心能力。

## 当前交付目标：M1 和 M2

1. 建立可重复安装、启动和测试的 Python FastAPI 后端与 React + TypeScript 前端。
2. 用户输入活动 URL 后，由 Playwright 在后端所在机器打开真实浏览器，用户在该浏览器内自行登录和操作。
3. 记录导航耗时、可见页面状态、加载失败及脱敏调试事件；未知页面明确标为未知。
4. 保存可复查的最小活动信息和研究记录，使下一次会话能延续研究。
5. 通过本地固定页面测试工作流程，不把模拟测试当成真实平台行为证据。

M2 的成功标准是“用户能打开活动并观察、记录页面加载信息”，不代表已经验证锁票规则、完成真实购票或能自动识别全部座位。

## 后续目标

官方页面中的目标流程为：进入活动 → 识别场次 → 进入选座 → 读取可见状态 → 按用户偏好筛选 → 用户确认 → 官方预订结果 → 官方支付。

后续优先研究 ALL TICKET。只有在观察证据足够、平台允许且用户确认的前提下，才讨论实际页面中的辅助行为。座位占用、订单与支付仍遵循官方流程。

本地模拟器应支持 100～500 个座位、区域和票档、并发选择、库存变化、锁定与超时释放、延迟和冲突。基于重复实验比较人工与辅助流程的找到座位耗时、选择耗时、预订成功率、冲突率和错误率。

## 当前不作为完成标准

- 确保热门活动购票成功。
- 推断任何平台的私有 API、锁票时刻或库存一致性。
- 自动选中真实座位、确认真实预订、提交订单或支付。
- 绕过验证码、排队、购买数量限制或反机器人措施。
- 在没有远程桌面支持的云环境中承诺用户能直接操作后端浏览器。
