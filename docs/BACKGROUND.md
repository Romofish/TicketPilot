# 项目背景

记录日期：2026-10-17（Asia/Shanghai）。来源：用户提供的 TicketPilot 项目交接文档及本次优先级调整。

TicketPilot 是供开发者本人及朋友使用的泰国票务平台购票辅助工具。用户在热门演出购票时遇到目标座位很快被选走、可见座位与实际可用性不一致、人工查找和确认较慢、进入页面时目标票档已经售罄等问题。

这些是用户报告的体验，不足以证明任何平台的库存、锁票或排队实现。工具希望通过正常浏览器会话观察流程，找到耗时和错误发生的位置，再在可控的本地模拟环境中评估辅助策略。

本次调整：**ALL TICKET 为首要开发和实际观察平台，TTM 为第二平台**。用户说“明天就要抢票了”，因此优先交付能启动、能人工登录、能记录页面状态的最小工具。

用户随后确认在自己电脑本地运行，并要求提供 GitHub Draft Release。目标活动 URL 为 `https://www.allticket.com/event/PlsLoveFanScreeningFinalEP`，用户报告开售时间为“明天泰国时间 11:00”。按本次客户端日期 2026-10-17 换算，对应 2026-10-18 11:00（Asia/Bangkok）/12:00（Asia/Shanghai）；这是对用户描述的日期解释，尚未经官方页面验证。另提供一个用户称已在售的参考活动，原始输入、规范化候选 URL 及访问证据见 `ALLTICKET_RESEARCH.md`。

初期仅用于本人及朋友。商业化、自动化策略及更广泛的平台支持不属于 M1/M2 的交付范围。

上下文按用途分开维护：

- `GOALS.md`：目标及阶段成功标准。
- `REQUIREMENTS.md`：用户已经确定的需求和操作边界。
- `ASSUMPTIONS.md`：尚待验证的条件及研究问题。
- `PROJECT_PLAN.md`：里程碑状态、实际验证结果、阻塞和下一步。
- `ALLTICKET_RESEARCH.md`、`TTM_RESEARCH.md`：各平台独立的观察证据。
- `DECISIONS.md`：工程决策与变更原因。
